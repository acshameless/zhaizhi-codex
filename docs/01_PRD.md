## 1. 背景与目标

### 1.1 背景

个人阅读的产出不是笔记，而是少数几句真正留下来的话。这些句子目前散落在微信读书、备忘录与纸书里，既不能按书回看，也不能跨书检索，且随时可能因平台变化而丢失。本项目的目标是把它们收进一个自己完全掌控、可以长期维护的地方。

### 1.2 目标

构建一个公开可访问的静态站点，实现三件事：句子存得住（Git + 纯文本）、句子找得回（句子级全文搜索）、句子会重逢（今日重逢与时间轴）。

### 1.3 成功指标

| 指标 | 目标值 | 验证方式 |
| --- | --- | --- |
| 单条录入耗时 | ≤ 30 秒 | 手机端实测：新增一段并提交 |
| 句子找回路径 | ≤ 2 步 | 打开站点 → 搜索 → 命中句子本身 |
| 中文片段召回 | 100% | 用任意 5 条真实摘抄的中间片段做回归测试 |
| 首屏 JS | ≤ 20 KB gzip（首页） | 构建产物检查 |
| 内容规模上限 | 500+ 本书 / 10,000+ 条不重构 | 构建耗时 ≤ 60 秒 |

## 2. 用户与场景

### 2.1 用户

- 作者（唯一写入者）：你。负责录入、标签、想法。
- 访客（只读）：通过链接进入的朋友或陌生人。无账号、无交互、无数据写入。

### 2.2 核心场景

1. 读到好句子：手机上在私有内容仓里追加一段，提交，30 秒内完成。
2. 回顾一本书：打开这本书的页面，看到这本书里所有摘抄与自己的想法。
3. 找回一句话：记得"活着本身"这几个字，输入，直接命中句子并跳回原书位置。
4. 随机重逢：打开首页，看到今天与你重逢的那一句。
5. 回头看时间：在时间轴上按时间浏览自己在某个阶段读了什么、摘了什么。

## 3. 范围

### 3.1 MVP（v0.1）

- [ ] 书架页：所有书按最近更新排序。
- [ ] 书籍详情页：一本书的全部摘抄与我的想法，句子级锚点。
- [ ] 全局搜索：句子级检索、按书/作者/标签筛选、高亮、键盘直达。
- [ ] 今日重逢：首页每天固定一句，可跳回原书。
- [ ] 时间轴：按时间分组的摘抄流。
- [ ] 私密开关：被标记的摘抄在构建期被完全剔除。
- [ ] 自动化部署：push 即构建、即发布。

书页与书架页是本 PRD 第 4 节的结构性出口（搜索结果必须回落到书，时间轴也依赖书籍数据），按必须项处理，见文末待确认 Q1。

### 3.2 V1.1（不阻塞 MVP）

- 标签页与标签云聚合。
- 漫游（随机跳到一本书 / 一句话 / 一个标签）。
- RSS 与站点地图优化、OG 图片自动生成。
- 暗色模式（暖黑，非纯黑）。
- 拼音搜索（输入 `huozhe` 命中《活着》）。
- 可视化后台：Keystatic 等 Git-backed CMS，浏览器里改内容，仍然只产生 Git 提交。

### 3.3 明确不做

账号体系、多用户、评论社交、编辑器、双链笔记、AI 生成内容、阅读进度追踪、书评社区、原生 App。

## 5. 功能需求

### FR-1 内容源与解析（P0）

系统从 `books/*.md` 读取全部内容，一本书一个文件，构建期解析为类型安全的 Book / Quote 对象。

验收标准：

1. 每个文件在构建期通过 Schema 校验；字段缺失或摘抄块格式错误时构建失败，并输出文件与行号。
2. 解析结果稳定可复现：同一份内容重复构建，输出完全一致。
3. 解析器有单元测试覆盖：正常文件、缺 id、缺原文、重复 id、空文件。

### FR-2 书架页（P0）

列出全部书籍，按最近更新排序，展示书名、作者、摘抄条数、最近摘抄时间与封面（缺省用纸张质感占位图）。

验收标准：50 本书时首屏渲染 ≤ 1.5 秒；书名与作者可点击进入书页；移动端单列。

### FR-3 书页（P0）

展示一本书的元信息与全部摘抄，按书内顺序排列。每条摘抄包含原文、章节/位置、标签、日期与"我的想法"（若有）。

验收标准：

1. 每条摘抄有稳定锚点 `#q-<id>`，可直接分享与跳转。
2. 页面可从任意摘抄处继续阅读，不因长内容卡顿（100 条摘抄实测）。
3. 提供"复制这一句"，格式为 `句子 —《书名》作者`。

### FR-4 全局搜索（P0）

句子级全文搜索，覆盖原文、书名、作者、标签与"我的想法"。

验收标准：

1. 中文子串可命中：输入"活着本身"必须命中包含该片段的句子（不依赖分词边界）。
2. 结果展示句子本身 + 出处（书名/作者/章节），点击跳转书页对应锚点。
3. 支持按书、作者、标签收窄结果；支持键盘操作（`/` 聚焦，↑↓ 选择，Enter 打开）。
4. 输入 150ms 内给出结果；无结果时给出明确空态与建议（换关键词 / 浏览书架）。
5. 搜索索引在构建期生成，运行时不发任何请求到第三方。

### FR-5 今日重逢（P0）

首页第一屏展示一句"今天与你重逢"的摘抄，来自全部非私密内容。

验收标准：

1. 同一天多次访问，展示同一句；次日自动更换（按日期确定性选取，可复现）。
2. 展示原文、出处与时间，可一键跳回原书位置。
3. 提供"再看一句"（当天的这句不变，仅本地浏览额外句子）。
4. 私密内容永不进入候选池。

### FR-6 时间轴（P0）

按时间倒序展示摘抄，按月分组。

验收标准：

1. 时间取值优先级：摘抄的 `摘于` → 书籍的 `read_finish` → 该条目首次提交日期。
2. 每条展示原文片段、书名与日期，可跳转书页锚点。
3. 1000 条数据下页面滚动流畅，无明显卡顿。

### FR-7 私密开关（P0）

摘抄或整本书可标记为私密。

验收标准：

1. 私密内容在构建期被剔除：不进入 HTML、搜索索引、时间轴与今日重逢。
2. 构建日志中不打印私密内容正文。
3. 语义边界在被明确记录：私密开关只控制站点展示，不保护仓库源文件（见风险 R2）。

### FR-8 录入工作流（P0）

支持两条录入路径：

1. 电脑：本地编辑器修改 Markdown → 提交 → 自动部署。
2. 手机：浏览器打开内容仓库对应文件 → 追加一段 → 提交。

验收标准：

1. 新增一条摘抄只需要修改一个文件的连续区块，不需要改动代码或配置。
2. 提交后自动构建并发布；构建失败时不发布，且能在提交记录中看到失败原因。
3. 提供一份可复制的"新增摘抄模板"，包含全部字段与注释。

### FR-9 构建与部署（P0）

验收标准：

1. 推送到主分支后自动构建并部署，全程无需人工操作。
2. 构建失败保留上一版本，站点不出现半成品。
3. 无数据库、无服务端运行时、无第三方接口依赖。

### FR-10 封面与静态资源（P1）

验收标准：封面图片存放于仓库内并压缩，不热链第三方图床；缺图时使用统一占位样式。

## 6. 数据模型

### 6.1 文件形态

一本书一个 Markdown 文件，位于 `books/<slug>.md`；`slug` 为 URL 友好的英文/拼音，书名用中文写在 frontmatter。

```markdown
---
title: 活着
author: 余华
slug: huozhe
cover: /covers/huozhe.jpg
publisher: 作家出版社
year: 2012
isbn: 9787506365437
status: read            # read | reading | want
rating: 5               # 1-5，可选
read_start: 2026-08-01
read_finish: 2026-08-12
tags: [小说, 人生]
private: false
---

### q-001

> 人是为了活着本身而活着，而不是为了活着之外的任何事物而活着。

- 章节: 第 3 章
- 位置: 第 132 页
- 标签: [人生, 苦难]
- 摘于: 2026-08-12
- 收藏: true
- 私密: false

我的想法：前半句给出理由，后半句划出边界。

### q-002

> 没有什么比时间更有力量。

- 位置: 第 214 页
```

### 6.2 解析规则（必须严格实现）

1. 文件以 YAML frontmatter 开头，字段结构由 Schema 校验。
2. 每个摘抄块以 `### <id>` 起始，`id` 形如 `q-001`，文件内唯一。
3. 块内第一个引用块（`>`）为原文，必填。
4. 引用块之后的 `- 键: 值` 列表为元数据，键值见下表。
5. 其余非空段落为"我的想法"。
6. `id` 一经分配不得修改（保证锚点与分享链接长期有效）；新增条目递增序号。

### 6.3 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 原文 | 是 | 摘抄正文，支持多行引用 |
| 章节 | 否 | 章名或序号 |
| 位置 | 否 | 页码 / 电子书位置 / 听书时间点，自由文本 |
| 标签 | 否 | 数组，与全局标签共用词表 |
| 摘于 | 否 | 日期，影响时间轴排序 |
| 收藏 | 否 | 布尔，用于未来"只看收藏" |
| 私密 | 否 | 布尔，构建期剔除 |
| 我的想法 | 否 | 一段个人评论，与原文分离 |

书籍级 frontmatter 中 `private: true` 表示整本私密，其下所有摘抄不进站点。

## 7. 搜索设计

- 方案：Pagefind（扩展版，内置中文/日文/韩文专用分词），构建期生成索引，运行时不依赖网络。
- 索引范围：摘抄原文、书名、作者、标签、我的想法。
- 过滤维度：书名、作者、标签；排序默认相关度。
- 交互：`/` 聚焦搜索框，输入即搜，↑↓ 选择，Enter 打开书页锚点；结果高亮命中片段。
- 边界：不做语义搜索、不做拼音（V1.1 再议）、不做同义词扩写。

## 8. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 首页 JS ≤ 20 KB gzip；搜索页脚本懒加载；LCP ≤ 1.5s（4G 模拟） |
| 响应式 | 移动优先，320px 起可用；手机端以"读"为主，录入走仓库网页 |
| 可访问性 | 对比度 AA、全键盘可达、语义化标签、尊重 `prefers-reduced-motion` |
| 隐私 | 私密内容构建期剔除；不接入任何第三方统计与追踪脚本 |
| 可维护 | 内容与代码解耦：只改 `books/` 就能维护站点 |
| 备份 | Git 即备份；提供一条命令导出全量 JSON/Markdown 快照 |
| SEO | 默认允许索引；`private` 内容从 sitemap 中排除；可一键切换为全站 noindex（见待确认 Q2） |

## 9. 技术架构

```text
books/*.md ──► 解析与校验（Schema）──► Astro 内容集合
                                      │
                                      ├─► 静态页面（书架 / 书页 / 时间轴 / 首页）
                                      └─► Pagefind 索引 ─► 搜索页
                                      │
                                Cloudflare Pages（push 即部署）
```

- 框架：Astro + TypeScript（默认零 JS，仅在搜索与"再看一句"处按需加载）。
- 样式：Tailwind CSS v4 + 设计令牌（Kami 色板与排版规则）。
- 搜索：Pagefind（构建期索引）。
- 部署：Cloudflare Pages，主分支自动发布，PR 生成预览。
- 目录结构：

```text
zhaizhi/
├── books/            # 内容（唯一数据源）
├── public/covers/    # 封面等静态资源
├── src/
│   ├── components/   # QuoteCard / BookCard / SearchBox / TimelineItem
│   ├── layouts/      # 基础版式
│   ├── lib/          # 解析器、查询、日期工具
│   ├── pages/        # 路由
│   └── styles/       # 设计令牌
└── docs/             # 本 PRD 与决策记录
```

## 10. 里程碑

| 阶段 | 内容 | 完成定义 |
| --- | --- | --- |
| M0 骨架 | 仓库、Astro 初始化、设计令牌、解析器与校验 | 一份示例书文件能渲染出书页 |
| M1 内容闭环 | 录入 20 条真实摘抄；书架页与书页上线 | 用真实内容而非假数据完成一次完整浏览 |
| M2 找回 | 搜索页 + 今日重逢 | 5 条中文片段回归测试全部命中 |
| M3 时间 | 时间轴 + 私密开关 + Cloudflare 部署 | 线上站点可用，push 即发布 |
| M4 打磨 | 移动端、排版、可访问性、性能预算达标 | 验收标准逐条通过 |

M1 完成后先用自己的真实内容试用一周，再决定 V1.1 的优先级。

### MVP 完成定义（DoD）

1. 上述 P0 功能验收标准全部通过。
2. 内容仓库里至少有 20 条真实摘抄、3 本书。
3. 线上站点可通过自定义域名访问（域名可选）。
4. 新增一条摘抄的全流程在手机与电脑各实测一次。

## 11. 风险

| 编号 | 风险 | 应对 |
| --- | --- | --- |
| R1 | 公开站点收录他人作品原文，存在版权与批量抓取风险 | 控制单条长度、标注出处、默认不提供全量导出；必要时切全站 noindex |
| R2 | 私密开关的语义被误解为"仓库级隐私" | 在 PRD 与站点关于页写明：仅控制站点展示；真私密需独立私有仓库 |
| R3 | 自制块格式解析脆弱，长期内容损坏 | 严格 Schema 校验 + 单元测试 + 构建失败即阻断发布 |
| R4 | 手机端在 GitHub 网页追加内容体验一般，录入摩擦上升 | 先实测；若超过 30 秒，V1.1 引入 Keystatic 类后台 |
| R5 | 中文搜索结果排序不理想 | 用真实语料做回归集，必要时补充自定义分词或字段权重 |

## 12. 待确认

1. 书架页与书页保留为 MVP 必须项（本 PRD 已按必须处理）。
2. 索引策略：默认允许搜索引擎收录；是否改为全站 noindex。
3. 仓库策略：单仓公开（内容与代码同仓公开）、单仓私有（站点公开、仓库私有），或双仓（公开代码 + 私有内容）。
